# 独立验收记录

范围：本地可运行原型及诚实的客户端接入边界。

## 验证结果

独立运行 `python3 -m unittest discover -s tests -v`：**32 项全部通过**，约 10 秒。包含 17 项适配器检查、4 项发现检查和 11 项集成检查。模型回复使用确定性测试替身；取消、超时、输出限制、子进程组、后台调度、MCP 协议和文件交接通过实际本机进程验证。此结果不等同于五个客户端全部自动接入，也不是模型综合能力排名。

## 复核中修复的问题

- 实测结果曾按运行模型保存、按配置模型查找，导致能力测试未用于路由；现已分开保存运行模型证据并按该证据选取样本。
- 重新发现曾保留已不在注册表中的客户端；现在替换当前注册表，防止失效入口继续参与自动路由。
- 尝试目录曾先于持久状态创建，可能产生不可恢复的孤立尝试；现在先保留尝试编号和运行状态，再把准备输入与执行统一纳入失败处理。
- 非对象审查 JSON 的处理和外部审查身份记录已修复。
- 第二个后台任务组曾因执行锁忙碌而退出；现在后台任务等待执行锁，直接运行仍可明确报告占用。
- 计划曾允许没有实际检查内容的验收对象；现在拒绝未知字段、空检查、关闭的审查条件及错误类型，并检查声明的文件 JSON 内容。

## 必须保留的实际边界

ChatGPT、WorkBuddy、DeepSeek Harness、豆包未验证的入口不能标成自动运行。MCP 服务已提供，但尚未写入或连接任何客户端配置；ChatGPT 的规划、分析和最终汇总应由实际 ChatGPT 任务提交，不由本地文本拼接冒充。

能力分数只来自已声明验收条件的通过率和耗时。小样本、未知模型及同模型审查不能解释为跨厂商能力证明。暂停采用协作取消，已发生的文件写入不会回滚；不明确的中断结果需要检查后重试。

适配器使用现有客户端登录，不读取密钥文件，也不把 API 密钥环境变量传给模型进程。细分文件工具权限依靠任务约束；操作系统沙箱控制可写范围，不等同于逐工具隔离，也不保证阻止所有无关文件读取。常见凭据格式日志脱敏已有测试，不能保证识别所有任意格式的敏感内容。

客户端入口说明见 [适配器说明](adapters.md) 和 [MCP 接入说明](mcp-setup.md)。
